# 现金流量表附表间接法——正式输入协议

## 一、协议目标

本协议规定补充资料第一部分的正式输入、字段含义、精度、校验和标准化结果。输入适配器可以支持不同Excel表头，但进入计算层的数据只能有一种标准结构。

## 二、输入文件与参数

用户按以下方式提供正式输入：

1. 经过“序时账分析器”处理的标准序时账Excel（`.xlsx`或`.xlsm`），通过 Windows 选择窗口提供；
2. 完整科目余额表Excel（`.xlsx`或`.xlsm`），通过 Windows 选择窗口提供；
3. 输出目录不通过窗口选择，由执行本技能的AI在对话中请客户直接输入绝对路径；目录不存在时按要求创建；
4. 可选的主表直接法经营活动现金流量净额或主表文件。

本次运行参数：

| 字段 | 必填 | 说明 |
|---|---|---|
| `entity_name` | 是 | 编制主体名称 |
| `entity_id` | 否 | 用户未提供时按主体名称生成稳定标识 |
| `period_start` | 是 | 会计期间开始日期 |
| `period_end` | 是 | 会计期间结束日期 |
| `functional_currency` | 是 | 本位币，默认人民币 |
| `currency_scale` | 是 | 本位币小数位数，人民币为2 |
| `display_unit` | 是 | 元、千元或万元，仅影响输出展示 |
| `net_profit_minor` | 是 | 净利润，使用最小货币单位整数 |
| `journal_preprocessing_confirmed` | 是 | 已提醒并确认序时账经过“序时账分析器”处理，且标准字段检查通过 |
| `net_profit_user_confirmed` | 是 | 客户已明确提供或确认本期净利润 |
| `net_profit_source` | 是 | 仅允许`user_provided`或`user_confirmed_statement` |
| `net_profit_source_note` | 是 | 客户提供方式或所确认报表的简要说明，不得为空 |
| `performance_materiality_minor` | 是 | 实际执行重要性水平 |
| `direct_cfo_minor` | 否 | 主表直接法经营活动现金流量净额 |
| `financial_entity_flag` | 是 | 是否属于金融企业 |

净利润和实际执行重要性水平不得只写在Excel自由文本中，必须进入运行清单。净利润必须由客户明确提供或确认；根据序时账推算的净利润只能作为核对数，不得代替客户确认金额。上述四个确认字段必须进入运行清单、配置快照和输入指纹。

运行参数进入计算前必须校验：主体和本位币不得为空；本位币小数位数必须是0至6的整数；展示单位只能是元、千元或万元；净利润和可选主表金额必须使用最小货币单位整数；实际执行重要性水平必须是正整数；金融企业标志必须是真正的布尔值，不能用字符串代替。

## 三、标准序时账输入

### 3.1 一行一分录

每行代表一条会计分录。多借多贷凭证保留为多行，由凭证唯一标识关联。

### 3.2 必填字段

| 标准字段 | 含义 |
|---|---|
| `source_file` | 原始文件名 |
| `source_sheet` | 原始工作表名 |
| `source_row` | 原始Excel行号 |
| `original_line_id` | 上游程序保留的原始行标识 |
| `voucher_date` | 凭证日期 |
| `fiscal_period` | 会计期间 |
| `voucher_type` | 凭证字或凭证类型 |
| `voucher_no` | 凭证号 |
| `voucher_id` | 主体、期间、凭证字和凭证号组成的唯一标识 |
| `line_no` | 凭证内行号 |
| `summary` | 摘要原文 |
| `account_code` | 末级科目代码 |
| `account_name` | 末级科目名称 |
| `account_path` | 一级至末级科目完整路径 |
| `level1_account_code` | 一级科目代码 |
| `level1_account_name` | 一级科目名称 |
| `debit_minor` | 借方金额，最小货币单位整数，可为负数表示红字 |
| `credit_minor` | 贷方金额，最小货币单位整数，可为负数表示红字 |
| `counterparty_level1` | 上游程序生成的对方一级科目，可包含多个 |
| `match_type` | 上游程序生成的匹配类型 |

### 3.3 条件必填字段

| 标准字段 | 适用情况 |
|---|---|
| `original_currency` | 存在外币核算 |
| `original_amount_minor` | 存在外币金额 |
| `exchange_rate_text` | 存在外币折算 |
| `quantity_text` | 数量核算参与事件判断 |
| `auxiliary_dimensions` | 存在客户、供应商、部门、项目等辅助核算 |
| `document_no` | 发票、合同或银行单据号可用于跨凭证关联 |

### 3.4 金额要求

1. Excel原始金额按文本读取并使用精确十进制转换；
2. 不对红字金额取绝对值；
3. 同一行借方和贷方原则上不能同时存在非零金额；
4. 零金额行可以保留为说明行，但不得形成金额片段；
5. 凭证借贷差额超过最小货币单位时属于阻断错误；
6. 原始金额、标准化金额和展示金额分别保存，不在中间过程反复换算单位。

## 四、科目余额表输入

### 4.1 科目层级字段

| 标准字段 | 必填 | 说明 |
|---|---|---|
| `account_code` | 是 | 科目代码 |
| `account_name` | 是 | 科目名称 |
| `account_path` | 是 | 完整科目路径 |
| `account_level` | 是 | 科目级次 |
| `parent_account_code` | 末级以外 | 上级科目代码 |
| `is_leaf` | 是 | 是否末级科目 |
| `account_nature` | 是 | 资产、负债、权益、成本或损益 |

### 4.2 余额与发生额字段

优先接受借贷分列：

| 标准字段 | 含义 |
|---|---|
| `opening_debit_minor` | 期初借方余额 |
| `opening_credit_minor` | 期初贷方余额 |
| `period_debit_minor` | 本期借方发生额 |
| `period_credit_minor` | 本期贷方发生额 |
| `closing_debit_minor` | 期末借方余额 |
| `closing_credit_minor` | 期末贷方余额 |

如果客户余额表使用“余额＋方向”表示，输入适配器转换为上述借贷分列结构，并保留原始值。

### 4.3 辅助项目

余额表存在客户、供应商、部门、项目等辅助项目时，标准化为：

| 标准字段 | 含义 |
|---|---|
| `owner_account_code` | 辅助项目所属末级科目 |
| `dimension_type` | 客户、供应商、部门、项目等 |
| `dimension_code` | 辅助项目代码 |
| `dimension_name` | 辅助项目名称 |
| `opening_debit_minor`等 | 该辅助项目对应余额和发生额 |

规则：

1. 辅助维度与科目层级平行；
2. 一个辅助项目必须关联到一个末级科目；
3. 汇总科目余额时不得再把辅助余额重复相加；
4. 同一末级科目存在多个辅助维度组合时，使用组合标识保存；
5. 只有需要拆分科目业务性质时才读取辅助维度，不把辅助维度强行转成会计科目。

## 五、表头识别与字段映射

1. 优先使用标准字段名和常见中文同义字段映射；
2. 表头跨多行时，输入适配器恢复合并单元格和层级表头；
3. 每次运行保存本次映射和判断依据；
4. 不跨客户、跨任务自动复用以前的映射模板；
5. 出现两个合理结构或字段映射歧义时，程序明确报错；由执行本技能的AI说明歧义并修正映射后重试，不静默猜测；
6. 只有结构差异达到实际执行重要性水平且存在强冲突证据时，才升级人工；
7. 最终映射写入运行清单和JSONL留痕。

## 六、标准化校验

### 6.1 阻断错误

出现以下问题不得声称生成正式结果：

- 序时账或余额表文件不可读；
- 主体或期间无法确定；
- 必填金额字段无法解析；
- 凭证大量不平且无法定位；
- 序时账与余额表本期发生额存在重大无法解释差异；
- 末级科目无法建立唯一层级；
- 输入文件在运行过程中发生变化；
- 未确认序时账已经过“序时账分析器”处理；
- 净利润或实际执行重要性水平缺失；
- 净利润未经客户明确提供或确认；
- 净利润来源仅为序时账推算，或来源说明为空。

系统应尽可能生成诊断结果和AI建议，但正式输出状态必须标记为阻断。

### 6.2 可自动修复

以下问题可自动标准化并留痕：

- 日期格式不同；
- 科目代码被Excel识别为数字；
- 金额带千位分隔符、括号负数或红字负数；
- 合并单元格导致的主体、期间或科目名称空白；
- 借贷余额使用方向列表示；
- 小计行、汇总行等结构行由上游“序时账分析器”处理；本技能遇到空白必填字段会明确报错并指出位置，不静默丢弃。

### 6.3 警告

- 摘要缺失；
- 辅助核算不完整；
- 对方一级科目包含多个且无法唯一匹配；
- 同一科目名称对应多个代码；
- 余额表发生额仅提供净额；
- 可选主表经营活动现金流量净额缺失。

警告不自动中止计算，后续规则和AI必须结合其金额影响继续判断。

## 七、标准化输出表

输入阶段必须形成并冻结：

1. `journal_lines.parquet`：标准序时账；
2. `trial_balance.parquet`：末级科目余额和发生额；
3. `account_nodes.parquet`：完整科目树；
4. `auxiliary_dimensions.parquet`：辅助维度及组合；
5. `config_snapshot.json`：本次运行配置快照；
6. 输入文件快照（序时账、余额表、规则文件）及其 SHA-256；
7. `checkpoint.json`：本阶段输入、规则和输出哈希的检查点。

计算模块不得再读取原始Excel，只能读取已经冻结的标准化结果。

## 八、输入阶段通过条件

同时满足以下条件才进入16项计算：

1. 输入快照完成；
2. 必填字段齐全；
3. 金额精确转换完成；
4. 科目树和辅助维度关系明确；
5. 所有标准化文件哈希已经写入检查点。

凭证借贷平衡检查、序时账与余额表发生额核对在定稿阶段执行；发现差异时阻断正式结论并输出诊断结果，不在准备阶段提前中断。
