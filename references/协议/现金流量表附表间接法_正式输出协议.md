# 现金流量表附表间接法——正式输出协议

## 一、输出目标

一次运行必须同时生成：

1. 普通用户可以直接查看和复核的Excel结果；
2. 后续程序可以继续使用的机器可读结果；
3. 能够追溯到原始分录、规则、AI判断和核对过程的证据文件。

Excel只负责展示，不承担核心计算。

正式工作簿固定包含18张可见工作表：1张“附表结果”＋1张“全量序时账”＋16张项目底稿（`01资产减值准备`至`16其他明确调整`）。每张项目底稿只展示进入本项目候选筛选的行（命中、排除、改归），在右侧追加本项目逐行判断注释，顶部统计未命中数量；另有一张“全量序时账”工作表完整保存输入序时账全部原始行并在右侧标注每行进入了哪些项目的候选，供人工复核各项目相关行是否完整。结果表与项目底稿之间提供32个双向内部链接（16个进入＋16个返回）。

## 二、输出目录

用户通过Windows文件夹选择窗口指定输出位置。系统在该位置下建立以 `run_id`（十六进制随机标识）命名的独立运行目录，每次运行不重复：

`<输出目录>\<run_id>\`

不得覆盖以前运行结果。输出文件名相同但运行批次不同时，必须位于不同目录。

## 三、Excel正式结果

正式工作簿：`现金流量表附表计算结果.xlsx`

### 3.1 “附表结果”工作表

至少包含：

| 字段 | 说明 |
|---|---|
| 项目名称 | 净利润及16项财务报表正式名称 |
| 调节金额 | 按输出展示单位 |
| 取数方式 | 规则或余额桥接、AI判断 |
| 明细笔数 | 纳入金额片段数量 |
| AI判断金额 | AI参与判断的金额合计 |
| 人工升级金额 | 达到升级门槛的AI建议金额 |
| 异常数量 | 会计异常和数据异常数量 |
| 核对状态 | 通过、警告或需人工复核 |

工作表表头下方列示：

- 净利润；
- 16项调节合计；
- 间接法经营活动现金流量净额；
- 主表直接法经营活动现金流量净额；
- 差异；
- 总对账状态。

### 3.2 “附表结果”进入项目底稿

“附表结果”中16个项目名称单元格各带一个内部链接，点击进入对应项目底稿顶部；每张项目底稿顶部有“返回附表结果”链接。合计32个双向链接，链接目标必须是工作簿内部位置，不得写入本机文件路径。

### 3.3 16张项目底稿（只放本项目相关行）

固定项目工作表名称：`01资产减值准备`、`02信用减值准备`、`03折旧、折耗`、`04无形资产摊销`、`05长期待摊费用摊销`、`06长期资产处置损失`、`07固定资产报废损失`、`08公允价值变动损失`、`09不属于经营活动的财务费用`、`10投资损失`、`11递延所得税资产减少`、`12递延所得税负债增加`、`13存货减少`、`14经营性应收项目减少`、`15经营性应付项目增加`、`16其他明确调整`。

每张项目底稿自上而下包含：

- 项目标题和返回链接；
- 项目冻结金额（立即可读，不依赖公式计算）；
- 余额桥接区域（不适用时显示“不适用”）；
- 本项目异常区域（无异常显示“无”）；
- 本项目判断明细（逐金额片段）及明细合计公式、差异公式（冻结金额减明细合计）；
- 本项目相关序时账（原始表头＋本项目候选行＋右侧25列项目注释），顶部统计“序时账共N行，本项目候选M行，其余未命中不逐行展示”，支持筛选并冻结顶部表头和前三个来源定位列。

每张底稿只展示进入本项目候选筛选的行（命中、排除、改归），未进入本项目的行不逐行写入，以顶部统计说明数量，避免在16张底稿中重复保存同一份全量序时账。空标题列仍占据原列位置，扩展辅助核算列值不得丢失。工作簿打开时自动重算公式。

### 3.4 “全量序时账”工作表

为人工复核各项目相关行是否完整，工作簿固定包含一张“全量序时账”工作表：完整保存输入序时账的全部原始行、全部原始列和原始顺序，并在每行右侧追加“候选项目”列，标注该行进入了哪些项目的候选筛选（升序、顿号分隔，未进入任何项目候选显示“无”）。人工可以把任一项目底稿的相关行与全量序时账对照，确认没有遗漏。

### 3.5 判断轨迹机器结果

工作簿不承担会计判断说明。规则判断、AI判断、正反证据、备选方案和最终金额占用统一保存在机器结果 `decision_trace.parquet`（见留痕协议），项目底稿通过金额片段标识与业务事件标识关联该轨迹。

### 3.6 原统一明细说明（保留历史口径）

统一明细字段至少包括：

- 项目序号和名称；
- 业务事件标识；
- 金额片段标识；
- 凭证日期、凭证号和原始行；
- 科目和对方一级科目；
- 摘要；
- 原始金额；
- 纳入金额；
- 符号；
- 处理结论；
- 规则编号；
- 是否AI判断；
- AI建议摘要；
- 是否人工升级；
- 排除或纳入理由；
- 占用状态；
- 证据事件标识。

### 3.7 余额桥接内容的位置

余额桥接不设独立工作表，分散在两处：

- 各项目底稿顶部的“余额桥接”区域：存货、经营性应收、经营性应付、递延所得税资产、递延所得税负债等适用项目，分别列示期初余额、期末余额、正常变化、非现金修正、非经营性修正和最终调节额；不适用的项目显示“不适用”；
- 机器可读桥接明细：随运行保存的Parquet桥接表（见留痕协议）。

### 3.8 核对结果内容的位置

核对结果不设独立工作表，分散在两处：

- “附表结果”工作表：每个项目的“核对状态”列，以及底部的总对账状态；
- 机器可读文件`reconciliation.json`：序时账与余额表借贷发生额核对、凭证平衡核对、金额占用完整性、项目互斥检查、允许的配套抵销、16项汇总检查、主表直接法与间接法总对账的完整明细。

### 3.9 异常与建议内容的位置

异常与建议不设独立工作表，分散在两处：

- 各项目底稿的“本项目异常”区域（无异常显示“无”）；
- 机器可读文件`issues.jsonl`：每条异常包含异常类型、金额、影响项目、事实描述、AI建议、建议理由、支持证据、相反证据、备选处理及金额影响、是否达到人工升级门槛和最终采用处理。

不得只写“请人工判断”。

### 3.10 运行信息内容的位置

运行信息不设独立工作表，保存在机器可读文件中（`result_summary.json`、`run_state.json`和`output_manifest.json`）：

- 主体和期间；
- 输入文件名和SHA-256；
- 运行标识；
- 代码、规则、协议和模型版本；
- 本位币、小数位数和展示单位；
- 净利润；
- 实际执行重要性水平；
- 运行状态；
- 成果性质：`formal_completed`或`diagnostic_only`；
- 输出文件清单。

各阶段耗时和峰值内存记录在`run_state.json`的`timings_seconds`与`peak_memory_bytes`字段。

## 四、机器可读结果

### 4.1 `result_summary.json`

包含：

- 运行和主体信息；
- 净利润；
- 16项金额；
- 间接法经营活动现金流量净额；
- 主表直接法经营活动现金流量净额；
- 差异、文件生成状态、总对账状态和成果性质；
- 规则、协议和代码版本。

数据质量统计由`reconciliation.json`的七类核对和`issues.jsonl`共同提供。所有正式金额使用最小货币单位整数，同时记录展示单位。

### 4.2 `adjustment_summary.parquet`

一行一个调节项目，字段包括项目编号、项目名称、金额、明细笔数、规则金额、AI金额、异常数量和核对状态。

### 4.3 `adjustment_details.parquet`

一行一个最终处理后的金额片段，是Excel“调节明细”的机器可读完整版本。

### 4.4 `amount_occupancy.parquet`

记录每个金额片段的原始金额、占用金额、剩余金额、占用项目和允许的配套抵销。

正式结果必须满足：

`原始金额＝已占用金额＋剩余金额`

所有应处理候选金额的剩余未分类金额为零。

### 4.5 `reconciliation.json`

记录：

- 序时账与余额表核对；
- 营运资本桥接；
- 递延所得税桥接；
- 金额占用完整性；
- 项目互斥；
- 直接法与间接法总对账；
- 每项差异的解释或阻断原因。

### 4.6 `issues.jsonl`

保存数据异常、会计异常、AI低置信度和人工升级事项。其记录格式遵循JSONL计算留痕协议。

### 4.7 `output_manifest.json`

列出全部正式输出文件、文件大小、记录数和SHA-256。

### 4.8 运行事件证据

正式输出同时包含`events.jsonl`和`event_index.parquet`。前者保存经过链式哈希校验的运行级事件，后者提供事件序号、事件哈希、阶段和事件类型查询入口；二者都必须写入`output_manifest.json`。

## 五、结果状态

文件生成状态、运行状态和成果性质必须分开记录。`file_status=exported`只表示文件已经成功生成；`status=blocked`表示仍存在阻断差异；只有总对账通过且没有未解决的重要人工复核事项时，`completion_status`才为`formal_completed`。缺少主表直接法经营活动现金流量净额、总对账未通过或仍有人工升级事项时，`completion_status`为`diagnostic_only`。缺少主表金额时，工作簿应显示“仅诊断、待总对账”；存在人工升级事项时显示“临时结果、待人工复核”。

### 5.1 运行状态

| 状态 | 含义 |
|---|---|
| `exported` | 文件已经成功生成；是否正式完成以`completion_status`为准 |
| `provisional_review` | AI已经给出完整临时结论，但存在达到门槛的人工升级事项 |
| `blocked` | 存在未分类金额或关键勾稽差异，只有诊断结果 |
| `failed` | 系统异常中止 |

旧口径中的`completed`对应`exported`且`completion_status=formal_completed`；`completed_with_warnings`对应`exported`且核对状态含警告。`provisional_review`仍必须对全部金额落数，并展示AI首选方案；人工未处理前不得标记为最终定稿。

### 5.2 金额处理状态

| 状态 | 含义 |
|---|---|
| `included` | 纳入某一调节项目 |
| `excluded` | 有明确理由排除 |
| `paired_offset` | 属于允许的配套抵销 |
| `ai_classified` | 由AI给出最终分类 |
| `review_required` | AI已落数，但达到人工升级门槛 |

不得使用`pending`、`unknown`或空白金额状态。

## 六、输出门禁

### 6.1 正式完成条件

1. 16项均已计算；
2. 所有候选金额均有处理结论；
3. 金额占用检查通过；
4. 互斥项目没有重复占用；
5. 余额桥接已完成；
6. JSONL留痕可读取且序号连续；
7. 输出文件哈希已生成；
8. 不存在阻断错误；
9. 人工升级事项已解决，或者明确输出为`provisional_review`。
10. 已取得主表直接法经营活动现金流量净额，且直接法与间接法总对账通过。

### 6.2 总对账差异

直接法和间接法不一致时：

1. 继续输出计算结果和差异分析；
2. 列出最可能来源及AI建议；
3. 状态根据差异金额和证据确定为警告、临时复核或阻断；
4. 不得随机分配差额；
5. 不得把差额塞入“其他明确调整”。

## 七、展示规则

1. 机器可读文件保存最小货币单位整数；
2. Excel按照用户选择的元、千元或万元展示；
3. 工作簿明确展示舍入差异；
4. 汇总数必须从冻结的机器结果导出；
5. 同一金额在Excel、JSON和Parquet中的符号必须一致；
6. 输出中不添加AI生成水印或签名；
7. 用户看不到内部文件名也能从Excel理解结论和原因。
