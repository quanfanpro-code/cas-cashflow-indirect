# 现金流量表附表间接法——模块化架构与中间数据协议

## 一、设计结论

采用模块化单体，不采用微服务，也不在第一阶段引入数据库。

原因：

1. 16个调节项目共享大量基础能力，放在一个进程中可以避免重复读取、重复匹配和跨服务传输。
2. 项目计算需要统一金额占用和总对账，拆成多个独立服务反而增加一致性风险。
3. Pandas、Parquet、JSONL和标准JSON已经能够满足当前数据规模、速度、断点恢复和查验要求。
4. 将模块边界和数据协议先稳定下来，将来确有超大数据或多人并发需要时，可以只替换存储或执行层，不重写业务规则。

## 二、模块分层

```text
Excel输入
  ↓
输入适配层
  ↓
标准化与结构校验层
  ↓
通用处理层
  ↓
部分项目共享层
  ↓
16项规则模块
  ↓
中央金额占用与汇总层
  ↓
核对、AI判断和质量门禁层
  ↓
Excel及机器可读输出
```

### 2.1 输入适配层

负责：

- Windows文件选择窗口；
- Excel工作表识别；
- 复杂表头恢复；
- 字段映射；
- 输入文件哈希；
- 原始值和原始行位置保留。

输入适配层只解决“数据在哪里、字段叫什么”，不判断会计性质。

### 2.2 标准化与结构校验层

负责：

- 金额精确转换；
- 日期、期间和凭证标识标准化；
- 科目层级恢复；
- 辅助维度拆分；
- 重复行和缺失行检测；
- 借贷平衡、期间范围和必填字段校验；
- 生成标准序时账表和标准余额表。

该层不包含任何一个调节项目的专用规则。

### 2.3 通用处理层

所有16项共用：

| 通用模块 | 职责 |
|---|---|
| 运行批次管理 | 创建运行标识、记录版本、控制断点恢复 |
| 凭证分组读取 | 按凭证读取完整分录，不按单行孤立判断 |
| 科目与辅助维度解析 | 识别科目层级、资产负债性质和辅助项目归属 |
| 损益结转识别 | 标记并排除具体技术性结转行 |
| 金额片段切分 | 把多借多贷凭证转换为可独立分类的最小金额 |
| 业务事件关联 | 将跨凭证的处置、报废、核销、重组等事项关联 |
| 证据收集 | 形成科目、对方科目、摘要、辅助核算和金额关系证据 |
| 规则执行 | 执行确定性纳入、排除和异常规则 |
| AI判断入口 | 对确定性规则不能唯一判断的金额片段给出最终建议 |
| 金额占用 | 统一处理互斥、部分占用和允许的配套抵销 |
| 余额核对 | 序时账与余额表本期发生额核对 |
| 留痕写入 | 追加JSONL事件，不允许覆盖历史 |

### 2.4 部分项目共享层

| 共享模块 | 服务项目 | 主要能力 |
|---|---|---|
| 减值桥接 | 第1、2、13、14项 | 区分计提、转回、核销、直接减记和原值修正 |
| 折旧摊销去向 | 第3、4、5、13项 | 识别进入损益、存货和非经营性长期资产的金额 |
| 长期资产事件 | 第3至7项 | 关联资产卡片、处置、报废、累计折旧摊销和清理损益 |
| 金融损益路由 | 第8、9、10项 | 区分公允价值、投资损益、融资费用和经营业务 |
| 递延所得税桥接 | 第11、12项 | 区分损益、权益、其他综合收益、合并和折算去向 |
| 营运资本桥接 | 第13、14、15项 | 期初期末余额、正常经营变化和非现金修正 |
| 特殊事项桥接 | 第16项及关联项目 | 政府补助、股份支付和债务重组的事件级抵销 |

共享层只提供计算能力，不直接决定最终项目金额。最终归属由16项规则模块和中央金额占用层确定。

### 2.5 16项规则模块

每个调节项目使用同一接口：

1. 声明候选科目和业务事件；
2. 调用通用层生成候选金额片段；
3. 调用所需共享模块；
4. 输出纳入、排除、异常和占用申请；
5. 计算项目汇总；
6. 执行项目内核对；
7. 输出证据和结果，不直接修改其他项目数据。

每个项目只保留真正独有的规则。科目标准化、凭证读取、AI调用、金额占用和留痕不得在16个模块中重复实现。

### 2.6 中央金额占用与汇总层

各项目可以并行生成候选和占用申请，但不得并行写入最终金额占用表。

中央层按固定顺序串行处理：

1. 读取全部占用申请；
2. 检查同一金额片段是否被互斥项目重复申请；
3. 识别允许的配套抵销；
4. 应用确定性优先级或AI最终建议；
5. 提交唯一金额占用；
6. 生成16项汇总和剩余金额检查。

这样可以同时利用项目并行计算速度，又避免多个模块抢写同一金额。

## 三、模块依赖纪律

1. 输入适配层不得依赖任何项目模块。
2. 通用层不得写入具体项目名称之外的业务结论。
3. 共享层可以被多个项目调用，但不得相互调用形成循环。
4. 项目模块可以依赖通用层和共享层，不得直接调用其他项目模块。
5. 所有项目只能通过占用申请影响最终金额占用表。
6. 输出层只读已冻结的计算结果，不得在导出Excel时重新计算或改数。

## 四、内部金额表示

1. 原始Excel金额先按字符串读取，再使用精确十进制解析。
2. 内部核心金额统一转换为最小货币单位整数，例如人民币元保留两位时使用“分”。
3. 同一运行批次必须记录本位币、金额单位和小数位数。
4. 最终输出时再转换为元、万元等展示单位。
5. 不使用二进制浮点数作为最终金额计算和勾稽依据。

### 5.1 输入快照

- 保存本次实际使用的输入文件副本或只读快照；
- 记录文件大小、修改时间和SHA-256；
- 原始文件变化后不得继续复用旧运行批次；
- 输入快照只读，后续阶段不得修改。

### 5.2 Parquet中间表

适合保存大量结构化数据：

- 标准序时账；
- 标准余额表；
- 金额片段；
- 候选和规则判断；
- 金额占用；
- 项目明细和核对表。

Parquet文件按阶段整体冻结。需要更正时生成新版本文件，不在原文件上逐行修改。

### 5.3 JSONL留痕

JSONL用于记录处理事实和判断过程，不代替Parquet计算表。每条记录只能追加，不能修改和删除。

### 5.4 小型JSON

用于：

- 运行清单；
- 规则和协议版本；
- 阶段检查点；
- 最终汇总和文件清单。

## 六、检查点与断点恢复

每个阶段完成时记录：

- 阶段名称；
- 开始和完成时间；
- 输入文件及哈希；
- 输出文件及哈希；
- 记录数和金额校验值；
- 代码版本；
- 规则版本；
- 协议版本；
- 状态：完成、失败或需要重新运行。

续跑条件：

1. 上一阶段状态为完成；
2. 输入哈希未变化；
3. 代码、规则和协议版本兼容；
4. 输出文件哈希和记录数校验通过。

任一条件不满足时，从受影响的最早阶段重新运行，不得继续使用已失效中间结果。

## 七、并发与写入纪律

1. 标准化阶段按工作表或数据块并行读取时，每个执行单元写独立临时结果。
2. 16项可以并行读取冻结数据并生成候选或占用申请。
3. 金额占用、JSONL序号分配、汇总结果和最终输出必须由单一写入者串行完成。
4. 文件先写入同目录临时文件，校验完成后再原子替换为阶段正式文件。
5. 同一文件不得被多个线程或模块同时写入。

## 八、失败与更正

1. 结构性输入错误不得由AI猜数后冒充正式结果。
2. 能够依据现有证据判断的业务分类不得简单推给人工。
3. 中途失败保留已完成检查点和错误留痕，不删除运行目录。
4. 更正判断时生成新事件和新版本中间表，原判断保留。
5. 不自动删除历史运行批次；后续如需清理，必须由用户明确指定。

## 九、第一阶段不做的事情

- 不拆微服务；
- 不引入消息队列；
- 不引入远程数据库；
- 不为16项分别复制一套输入、AI和留痕代码；
- 不在Excel公式中承担核心计算；
- 不使用随机残差分配；
- 不把JSONL当作大表计算引擎。

上述边界是当前技术决定。只有真实样本表明Parquet和单进程中央汇总不能满足数据规模时，才评估替换执行或存储层。
