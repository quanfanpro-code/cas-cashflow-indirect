# 📘 现金流量表补充资料（间接法）使用说明

这是一套帮助你编制和复核现金流量表补充资料的技能。它从客户确认的净利润出发，分析标准序时账和科目余额表，把净利润逐步调节为经营活动产生的现金流量净额，并保存每一步的取数依据、判断理由和核对结果。

你不需要懂编程，也不需要自己填写电脑路径。正常使用时，只要在对话中说明要编制现金流量表补充资料，系统会弹出 Windows 文件选择窗口，并逐步询问缺少的业务信息。

## 📦 自包含范围

除运行环境和本次业务输入外，这套技能是自包含的。计算代码、16项规则、输入输出协议、判断留痕协议、准则资料、知识库和工作簿生成逻辑都保存在技能目录内。

- 运行环境是指Python以及`pandas`、`pyarrow`、`openpyxl`、`xlsxwriter`四个已声明的表格处理库；运行前会自动检查，缺少时会明确提示安装。
- 不需要Node，不需要额外的表格生成程序，也不依赖其他会计判断Skill。
- 标准序时账、科目余额表、客户确认净利润、实际执行重要性水平和可选的直接法金额属于本次业务输入，不属于技能缺失内容。
- “序时账分析器”是标准序时账的上游生产工具。本技能从符合输入协议的标准序时账开始处理，不绑定某个特定分析器。
- 财政部网页链接用于说明资料来源，并在准则修订、特殊新业务或资料冲突时核验规则是否仍然有效；日常计算和常规判断不依赖联网。

## 🎯 它能帮你完成什么

这套技能主要完成以下工作：

- 检查序时账是否经过规定的预处理；
- 读取标准序时账和科目余额表；
- 识别科目层级以及与科目平行的客户、供应商、部门、项目等辅助信息；
- 计算现金流量表补充资料的16个调节项目；
- 防止同一笔金额被两个互斥项目重复使用；
- 对不能仅靠固定规则判断的事项给出AI建议和建议理由；
- 把间接法计算结果与账簿、余额变化及已提供的直接法结果进行核对；
- 输出电子表格结果、调节明细、异常说明和可追查的计算记录。

## 👥 谁适合使用

以下人员都可以使用：

- 需要编制现金流量表补充资料的企业财务人员；
- 需要复核现金流量表间接法的审计人员；
- 已经取得标准序时账和科目余额表，但不想人工逐项筛选大量分录的人；
- 希望每个重要判断都有建议、理由和证据，而不是留下大量“待判断”的人。

## 📂 使用前准备

开始前，通常需要准备以下资料。

### 1. 标准序时账

标准序时账不是财务软件直接导出的原始序时账。它必须先经过既有的“序时账分析器”处理，并且至少能够识别：

- 每条分录的科目；
- 对方科目；
- 借方或贷方金额；
- 凭证和分录之间的关系；
- 对方科目的匹配类型。

为什么必须先处理？因为原始序时账通常只有一行借方、一行贷方，却没有明确告诉系统每一行与哪一行相对应。如果缺少对方科目和匹配类型，系统无法可靠识别资产处置、减值计提、核销、往来变化等业务，也容易重复取数。

如果你选择了未经处理的原始序时账，系统应当停止本次计算，并提醒你先运行序时账分析器。它不会在现金流量表计算过程中偷偷重做对方科目匹配。

### 2. 科目余额表

余额表可以使用已经清洗过的版本。它通常需要包含科目名称、期初余额、本期借方发生额、本期贷方发生额和期末余额。

实务中的余额表可能同时存在两套平行结构：

- 第一套是一级科目、二级科目、三级科目等科目层级；
- 第二套是客户、供应商、部门、项目等辅助信息。

辅助信息不是下级科目，不能和科目层级重复相加。系统会尽量识别这两套结构，并把辅助信息关联到所属科目，但不会把同一金额既按科目汇总一次、又按辅助项目重复汇总一次。

### 3. 客户确认净利润

净利润是间接法计算的正式起点，必须由客户明确提供，或者由客户确认正式财务报表上的金额。

系统可以根据序时账计算一个利润核对数，但这个核对数不能代替客户确认净利润。原因很简单：序时账中可能存在结转分录、报表调整、合并抵销、账外调整或尚未入账事项，仅凭序时账推算可能与正式报表不一致。

如果没有提供净利润，系统必须主动询问，不能自己猜一个金额开始正式计算。

### 4. 实际执行重要性水平

“重要性水平”可以理解为：多大的金额或差异值得单独升级复核。

它不是用来掩盖差异，也不是允许系统随意忽略小金额。它主要用于判断某个证据冲突的事项是否需要升级人工复核。

即使事项低于重要性水平，系统也应当给出自己的首选建议，不能把它丢进“待判断”清单。

### 5. 直接法经营活动现金流量净额

如果你已经有现金流量表主表中的经营活动现金流量净额，最好一并提供。系统会把它与间接法结果进行总对账。

如果暂时没有，也可以先做诊断计算，但不能把缺少主表总对账的结果说成已经正式核对完成。

## 🚀 开始使用

### 第一次开始

你只需要在对话中说明：要使用现金流量表间接法技能编制或复核补充资料。

系统接下来应当按顺序完成这些动作：

1. 先提醒你，序时账必须经过序时账分析器处理；
2. 弹出窗口，让你选择标准序时账；
3. 弹出窗口，让你选择科目余额表；
4. 弹出窗口，让你选择本次结果保存到哪个文件夹；
5. 检查标准序时账是否具备对方科目和匹配类型；
6. 询问或确认主体名称、会计期间、净利润及其来源；
7. 询问实际执行重要性水平；
8. 如果你有直接法经营活动现金流量净额，再一并记录；
9. 开始读取、计算、判断和核对。

所有文件路径都通过 Windows 选择窗口取得。你不需要手工复制一长串盘符和文件夹地址。

### 继续上次任务

如果上次计算停在AI判断、等待补充资料或重新输出阶段，可以要求继续上次任务。

系统会弹出窗口，让你选择上次的“运行目录”。运行目录是系统保存本次输入快照、中间结果和运行状态的文件夹，不是最后只存放电子表格的交付文件夹。

如果误选了最终结果文件夹，系统会告诉你缺少运行状态文件，并要求重新选择，不会拿错误目录继续计算。

### 查看状态

你可以直接询问“上次计算到哪一步了”或“为什么还没有正式结果”。系统应当读取运行状态，并用大白话告诉你属于以下哪一种情况：

- 正在等待AI判断；
- 缺少客户确认净利润或其他必要信息；
- 输入文件在中途发生变化，旧任务已经作废；
- 核对没有通过，目前只有诊断结果；
- 全部门槛通过，已经生成正式结果。

## 🔍 运行逻辑

下面用不涉及编程的方式解释系统内部会做什么。

### 第一步：冻结本次输入

系统会为本次计算建立一个独立运行批次，把所选输入作为本次计算的固定快照，并记录文件指纹。以后如果文件发生变化，系统能够识别出来，不会把新旧数据混在同一次计算中。

### 第二步：把电子表格转换成便于计算的数据

电子表格适合人查看，但不适合在每一步反复查找和计算。系统读取后，会在内部转换成结构清楚的数据表，用于筛选、分组、计算和保存过程记录。

电子表格主要出现在输入端和输出端。内部计算不会依赖大量人工公式，也不会在一个工作簿里层层堆叠隐藏公式。

### 第三步：识别科目和辅助信息

系统分别识别科目层级和辅助信息，建立它们之间的关联。它会防止以下常见错误：

- 把客户名称误认为下级科目；
- 把项目辅助信息与科目金额重复相加；
- 把一条同时带多个辅助信息的记录拆成多套金额；
- 因为余额表有汇总行和明细行而重复汇总。

### 第四步：筛选16个调节项目

系统按照已经确认的业务规则，逐项筛选金额。主要包括资产减值、折旧与摊销、资产处置损益、固定资产报废损失、公允价值变动、财务费用、投资损益、递延所得税、存货和经营性往来变化等项目。

对于资产减值等项目，正式取数主要来自标准序时账。余额表用于检查余额桥接是否合理，不能仅用余额表发生额代替计提、转回、核销和处置的逐笔分析。

### 第五步：切分和占用金额

一条复杂分录可能只有一部分金额属于某个调节项目。系统会把它拆成可以独立判断的金额片段，再记录每个片段最终由哪个项目使用。

中央防重复规则会阻止同一金额被两个互斥项目同时使用。确实属于同一经济事项的配套影响，例如折旧计入存货后同时影响折旧项目和存货变化，则按照明确规则保留，不会机械地全部删除。

### 第六步：处理不能直接确定的事项

固定规则能够唯一处理的事项直接完成，不产生新的人工事项。只有固定规则不能唯一判断的金额，才进入AI分析。

系统会提供金额、凭证摘要、科目、对方科目、候选项目和已有证据，避免让AI只看一句含糊摘要猜答案。

### 第七步：核对余额和总额

分类完成后，系统会检查：

- 序时账取数能否与相关科目变化衔接；
- 期初余额、本期变化和期末余额能否桥接；
- 是否存在未分类金额；
- 是否存在互斥项目重复使用同一金额；
- 间接法经营活动现金流量净额能否与直接法主表金额一致。

系统不会为了让结果相等，把不明差额随便塞进“其他”项目或第16个项目。核对失败时，它应当回到来源凭证、余额桥接和金额归属查原因。

### 第八步：生成结果和过程记录

只有交付门槛全部通过，系统才生成正式结果。计算明细、判断理由、核对结果和异常建议会同时保存，便于以后复查。

## 🤖 AI建议如何形成

这里的AI是指当前对话中的人工智能判断能力。计算程序本身不单独连接外部模型，也不要求你配置模型账号或密钥。

遇到疑难会计事项时，判断顺序如下：

1. 先看已经固化的确定性规则；
2. 再看技能内保存的财政部准则原文；
3. 再查技能内知识库中的应用解释和案例；
4. 只有遇到修订、新业务、资料冲突或需要确认规则时效时，才查询财政部当前有效原文和实施问答；常规事项直接使用技能内资料即可完成。

AI建议必须包含：

- 唯一首选项目；
- 建议纳入还是排除；
- 建议金额；
- 判断理由；
- 支持建议的证据；
- 与建议相反的证据；
- 没有采用其他分类的原因；
- 对经营活动现金流量的影响；
- 判断把握程度。

不能只输出“建议人工判断”，也不能把所有有一点不确定的事项都推给使用者。

## 👤 什么情况下需要人工复核

只有同时满足以下两个条件，才升级人工复核：

1. 事项金额达到实际执行重要性水平；
2. 不同证据之间存在强冲突，无法仅靠现有资料可靠消除。

即使升级人工，系统仍然必须保留AI建议、建议理由和金额影响。人工看到的应当是“系统建议怎么处理以及为什么”，而不是一张没有意见的待办清单。

以下情况通常不应直接推给人工：

- 固定规则已经可以唯一判断；
- 金额较小且证据没有强冲突；
- 只是摘要写得不够漂亮，但科目、对方科目和业务关系已经清楚；
- 系统可以通过其他分录、余额变化或同类凭证找到充分证据。

## 📊 查看结果

正式完成后，最重要的结果是《现金流量表附表计算结果》电子表格。一般还会同时保存以下内容：

- 16个调节项目的汇总结果；
- 每个项目的逐笔调节明细；
- 余额桥接结果；
- 直接法与间接法总对账；
- AI判断和人工升级数量；
- 异常事项与处理建议；
- 本次运行的输入、规则和结果指纹；
- 可以继续追查的计算过程记录。

### 电子表格里一共有18张表

正式电子表格固定包含 **1 张结果表 + 1 张全量序时账 + 16 张项目底稿**，共 18 张表：

- **附表结果**（第一张）：净利润、16 个调节项目、调节合计、间接法结果和总对账状态都在这张表上，是进入底稿的总入口。
- **全量序时账**（第二张）：完整保存输入序时账的全部行，每行右侧标注“候选项目”（这一行进入了哪些项目的筛选），供人工复核用。
- **16 张项目底稿**：分别是“01 资产减值准备”到“16 其他明确调整”，每张对应一个调节项目。

### 从结果表进入项目底稿

在“附表结果”里，点击任意一个项目名称（比如“资产减值准备”），就会跳到对应项目的底稿顶部。底稿顶部有这一项目的冻结金额、余额桥接、异常和逐笔判断明细。

### 返回结果表

每张项目底稿的右上角都有“返回附表结果”链接，点击即可回到结果表。结果表和 16 张底稿之间一共有 32 个这样的双向链接（16 个进入 + 16 个返回）。

### 每张底稿里能看什么

每张项目底稿都从上到下包括：项目冻结金额、余额桥接、本项目异常、逐笔判断明细（带合计公式）、以及**本项目相关序时账**。为节省篇幅，每张底稿只展示进入本项目筛选的行（命中、排除、改归），顶部会说明“序时账共多少行、本项目候选多少行、其余未命中多少行”；需要逐行核对全量数据时，用第二张“全量序时账”表。序时账区域每一行右侧都追加了本项目专属的逐行注释，可以按“项目筛选状态”筛选：

- **命中**：这一行进入了本项目，旁边有规则编号、判断理由和金额占用；
- **本项目未命中**：这一行没有进入本项目，但不删除，方便核对；
- **是否人工智能判断**：筛“是”可以看到 AI 建议、理由、支持证据、相反证据和未采用的方案；
- **是否人工升级**：筛“是”可以看到需要人工复核的事项；
- **异常区域**：与项目有关的会计或数据异常集中在本项目底稿里。

### 为什么 16 张底稿不重复放全量序时账

如果 16 张底稿都完整放入同一份序时账，文件会非常庞大（16 倍重复）且生成很慢。因此每张底稿只放本项目筛选相关的行，完整序时账单独放在第二张“全量序时账”表里，需要时可以对照复核各项目相关行是否完整。

### 序时账行数接近上限会怎样

每张项目底稿只放本项目相关行，“全量序时账”表保存完整序时账（几千行 × 几十列）。如果序时账行数多到接近电子表格单表上限（约 104 万行），程序会在生成前明确报错并提示拆分序时账，不会悄悄截断或丢行。

查看结果时，先看总核对是否通过，再看调节项目汇总，最后按需要下钻到逐笔明细和异常说明。

## ✅ 什么才算正式完成

同时满足以下条件，才能称为正式完成：

- 所有需要分类的金额已经处理；
- 没有互斥项目重复使用同一金额；
- 余额和项目内核对通过；
- 必须提供主表直接法经营活动现金流量净额，且总对账通过；
- 最终文件的完整性检查通过；
- 没有仍会改变结果的重要人工复核事项。

文件成功生成不等于正式核对完成。系统必须先检查上述门槛。缺少主表直接法经营活动现金流量净额时，仍会生成完整底稿，但成果明确标为“仅诊断、待总对账”；补充主表直接法经营活动现金流量净额后，再继续完成正式核对。

系统分别记录三件事：文件状态说明底稿是否成功生成；运行状态说明是否存在阻断差异；成果性质说明能否作为正式核对完成。即使总对账失败，已经生成的底稿仍显示“文件状态：已导出”，但运行状态为阻断、成果性质为诊断，不会把有差异的结果冒充正式完成。

## ⚠️ 核对失败怎么办

核对失败不等于程序坏了，通常表示输入、账务处理或分类之间存在需要解释的真实差异。

系统应当保留诊断结果，并优先告诉你一个最值得先处理的动作，例如：

- 补充客户确认净利润；
- 改用经过序时账分析器处理的标准序时账；
- 检查某个金额较大的处置或减值凭证；
- 检查余额表的科目层级与辅助信息是否被重复汇总；
- 补充直接法经营活动现金流量净额；
- 因输入文件变化而新建运行批次。

它不应一次扔给你几十项没有优先顺序的“待判断”。

## 🧭 常见问题

### 我只有原始序时账，可以直接使用吗？

不可以。请先使用既有序时账分析器生成包含对方科目和匹配类型的标准序时账。

### 为什么系统一定要问净利润？

因为净利润是间接法的正式起点。系统根据序时账推算的利润只能用于核对，不能代替客户确认金额。

### 重要性水平由谁提供？

通常由项目负责人或审计项目组根据项目情况确定。系统会使用它判断证据冲突事项是否需要升级人工，但不会用它掩盖差异。

### 余额表里既有科目又有客户和项目，会不会重复？

系统会把科目层级和辅助信息作为两套平行结构识别，避免把同一金额重复汇总。遇到特殊格式时，应先查看余额结构识别结果和异常提示。

### 系统会不会把所有异常都推给人工？

不会。系统必须先给出唯一AI建议和理由。只有金额重要且证据强冲突时才升级人工。

### 没有直接法经营活动现金流量净额还能算吗？

可以先做诊断计算，但缺少最终总对账时，结果不能称为正式完成。取得主表金额后可以继续核对。

### 为什么不能用最后一个项目把差额倒挤平？

因为倒挤只能让数字表面相等，不能证明分类正确。系统必须回到凭证、余额和金额归属查明差异来源。

### 输入文件改过以后能继续旧任务吗？

不能直接继续。输入变化后应新建运行批次，防止新数据与旧判断混用。

### 最终去哪里找结果？

结果保存在你开始任务时通过 Windows 窗口选择的输出文件夹中。正式结果、明细、核对和异常说明都从该文件夹查看。

## 🛡️ 使用提醒

- 不要把未经处理的原始序时账冒充标准序时账；
- 不要让系统自行推算净利润后直接作为正式起点；
- 不要把科目辅助信息当成下级科目重复汇总；
- 不要因为金额较小就删除过程记录；
- 不要为了配平把差额随便塞进“其他”项目；
- 不要在核对未通过时把结果称为正式完成。

## 🌟 最简单的理解方式

你负责提供正确的账簿、客户确认净利润、重要性水平和可选的主表金额。

系统负责读取数据、计算16个项目、查找证据、给出AI建议、防止重复、完成核对并保存结果。

真正需要人工介入的，应当只剩下金额重要且证据确实强冲突的少数事项，并且每一项都附带系统建议和理由。
